# Cost Manager Pro — Architecture

This document describes the architecture **as it exists** (M0 baseline
`bd28ad0`, updated for M1), then the approved direction. Decisions and their reasons are
recorded in [`DECISIONS.md`](DECISIONS.md).

> **Legacy references:** source comments that cite `docs/ARCHITECTURE.md §6`
> or `docs/TEST_PLAN.md §15` mean the archived course documents in
> [`archive/course/`](archive/course/README.md).

## 1. Current stack

| Concern | Technology |
|---|---|
| Language | JavaScript (ES modules) and JSX |
| UI | React 19, MUI 9 (Emotion), `@mui/icons-material` |
| Charts | Recharts 3 |
| Build | Vite 8 (`@vitejs/plugin-react`) |
| Persistence | Browser `localStorage` |
| Network | Fetch API (exchange rates only) |
| Export | `write-excel-file` (XLSX), `jspdf` with `jspdf-autotable` (PDF). Both load only when an export is used |
| Tests | Vitest 4 with jsdom, Testing Library |
| Lint | ESLint 10 (flat config) |
| CI/CD | GitHub Actions `ci.yml` (lint, test, build on PRs to `main` and pushes to `main`). Vercel configuration in `vercel.json`; **not connected or deployed yet**. See [`DEPLOYMENT.md`](DEPLOYMENT.md) |

There is no backend, no authentication, no router, and no global state
library.

## 3. Layering

```text
pages / components   (React + MUI: input, display, loading/error states)
        │
        ▼
services, hooks, utils   (no React or MUI inside lib/utils/services)
        │
        ▼
lib/db.js, lib/exchangeRatesCache.js
        │
        ▼
localStorage, fetch
```

- Components never read or write `localStorage` directly.
- Currency conversion lives only in `utils/currency.js`
  (`amount / rates[source] * rates[target]`, where each rate means "units
  per 1 USD").

## 4. Data model and storage

Full details: [`DATA_STORAGE.md`](DATA_STORAGE.md).

| Key | Contents |
|---|---|
| `cost-manager-pro:costsdb:v2:costs` | `{ schemaVersion: 1, costs: [...] }` |
| `cost-manager-pro:costsdb:v2:costs:previous` | One safety copy, kept before a dataset is replaced |
| `cost-manager-pro:settings` | `{ exchangeRatesUrl? }` |
| `cost-manager-pro:exchange-rates-cache` | The last validated rates `{ USD, ILS, GBP, EURO }` |

Expense record:

```javascript
{
  id: "uuid",                       // generated by db.js
  sum: 12.5,                        // number, original amount
  currency: "ILS",                  // USD | ILS | GBP | EURO (original, never overwritten)
  category: "Food",
  description: "Lunch",
  date: { day, month, year, hour, minute }   // local wall-clock parts
}
```

Since M1:

- All persistence goes through `lib/storage/costStore.js`. Each operation
  re-reads storage and validates every record.
- Unusable data (`damaged`, `unsupported`, `unavailable`) throws a
  `StorageError` with a code. Saving over it is refused.
- Replacing the whole dataset keeps the previous value first.

Remaining limitations are listed in [`DATA_STORAGE.md`](DATA_STORAGE.md) §8.

## 5. Exchange rates

1. `main.jsx` refreshes rates once at startup. A failure is ignored without
   telling the user.
2. Reports and charts try to refresh rates again before each "Generate".
3. Rates are validated: all four currencies present, positive, finite, and
   USD exactly 1. They are then cached.
4. `db.getReport()` is **synchronous**. It reads the cache, and when a
   cross-currency total is needed but there is no cache, it throws an
   error.

Steps 1–4 come from the course's synchronous `getReport()` rule. That rule
no longer applies (see the archive classification, item 1), so this design
can be changed in M2.

## 6. Navigation and state

- `App.jsx` keeps `activePageId` in React state. There are no URLs, so a
  refresh always returns to the Dashboard.
- Each page keeps its own form, result, and error state.

## 7. Testing

- 35 test files (441 tests) as of M1, covering:
  - the expense API and both `db.js` versions
  - storage safety, migrations, backup and restore, and isolation from the
    original app (`tests/storage/`)
  - currency, categories, dates, chart and yearly aggregation, sorting,
    exports, and services
  - every page
- No end-to-end tests, no accessibility checks, no coverage report yet
  (M7).
- Run: `npm run lint`, `npm test`, `npm run build`.

## 8. Approved direction

These rules guide future milestones. They are not implementation
commitments:

- **Keep:**
  - React, Vite, MUI, Recharts, and Vitest
  - business logic stays outside the UI
  - one shared list of currencies and one conversion function
  - local-first storage
  - static hosting with no secrets needed to run
- **Possible choices (each needs a justified ADR before it is adopted):**
  - React Router (or another URL routing approach)
  - IndexedDB (instead of or alongside `localStorage`)
  - Vercel, Netlify, or GitHub Pages for hosting
  - an i18n library ([`LOCALIZATION.md`](LOCALIZATION.md) §12)
  - TypeScript
  - Playwright for end-to-end tests
  - a free exchange-rate provider
- **Any major change** (new dependency, storage engine, routing, data
  format) must state the problem it solves, the alternatives considered,
  how existing data migrates, and how it will be verified.
